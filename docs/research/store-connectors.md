# Store connectors research: Shopify and WooCommerce (P4-06b)

**Retrieval date:** 2026-09-27

**Scope:** what HyFib needs to connect a company's own Shopify or WooCommerce store and keep a copy of
its orders and products in step with it:

- authenticated setup;
- webhook verification and deduplication;
- recovery when webhooks are missed;
- uninstall and privacy requests;
- order and product fields;
- money formats and limits.

## Method statement

- **Blocked sources:** this environment's network policy refused `shopify.dev`,
  `woocommerce.github.io`, `developer.woocommerce.com`, `api.github.com` and `codeload.github.com`.
  No shopify.dev page was opened directly.
- **Official packages on npm (reachable). Most Shopify evidence comes from these:**
  - **`@shopify/dev-mcp` 1.16.0** (published 2026-09-25). Shopify's own developer MCP server. It
    ships the Admin GraphQL introspection schemas for 2025-10, 2026-01, 2026-04, 2026-07 and
    2026-10, the list of supported versions, and per-field access notes (`offline_scopes`). Types,
    fields, enums and their descriptions were read from `admin_2026-07.json.gz`.
  - **`@shopify/shopify-api` 15.0.0** (published 2026-09-17). Shopify's official Node library. Its
    TypeScript sources were recovered from the package's source maps and read for:
    - OAuth: begin, callback, refresh, token exchange and client credentials;
    - HMAC and shop validation;
    - webhook validation and the webhook header names.
  - **`@shopify/admin-api-client` 2.0.0:** the Admin GraphQL URL and access-token header.
- **Raw GitHub (reachable):**
  - `Shopify/shopify-app-js`, `main` branch: the library's CHANGELOG and docs (`docs/guides/oauth.md`,
    `docs/reference/auth/*.md`, `docs/guides/webhooks.md`).
  - `woocommerce/woocommerce`, `trunk` branch: the plugin sources that implement the behaviour. Read:
    - `class-wc-webhook.php`, `wc-webhook-functions.php` and `class-wc-webhook-data-store.php`;
    - `class-wc-auth.php` and `class-wc-rest-authentication.php`;
    - the REST controllers for orders, products, webhooks and the CRUD base.
  - `woocommerce/woocommerce-rest-api-docs`, `trunk` branch: the Markdown source of the official
    REST API v3 documentation. Read the pages for authentication, orders, products, webhooks and
    setting options.
- **Web search:** WebSearch with `allowed_domains: shopify.dev` for facts that live only in
  Shopify's prose documentation and changelog:
  - delivery timeouts and retries;
  - compliance webhooks;
  - protected customer data;
  - expiring tokens;
  - rate limits.

  A search result is a title, a URL and a model-written summary. Rows that rest on one are marked
  SH-SNIP, and their wording is not a quote.
- Nothing here was tested against a real Shopify store or a real WooCommerce site.

## Unconfirmed or conflicting

- **Delivery updates (SH-034):** whether Shopify changes an order, or sends `orders/updated`, when
  a shipment is delivered is unconfirmed. HyFib therefore reads orders in transit again on a
  schedule (see Implications 8) instead of relying on order webhooks.
- **Shopify dates and lifetimes:** the token lifetimes (60 minutes, 90 days), the dates the expiring
  tokens became required, the retry schedule (8 times over 4 hours), the 5-second timeout and the
  30-day deadline for compliance requests come from search summaries (SH-007, SH-008, SH-025,
  SH-027). They must be checked on shopify.dev before release.
- **Compliance payloads (SH-027):** only `customers/redact` was seen, and only in a summary. For
  `customers/data_request`, HyFib reads `shop_domain`, `customer` and `orders_requested` when present
  and keeps the request for the company without relying on other fields.
- **Protected customer data (SH-020):** which order fields a HyFib app would be approved for is
  Shopify's decision. Unapproved fields arrive redacted, so orders may have no customer name, phone
  or email. HyFib shows "not shared by the store".
- **The WooCommerce webhook `secret` default (WC-011)** differs between the source and the docs.
  HyFib always sends its own secret.
- **WooCommerce `checkout-draft` orders:** the orders page of the docs does not list this status,
  which block-based checkouts use. HyFib shows any status it does not know as the raw status text.

## Implications for HyFib

1. **Shopify app:**
   - **Connection:** one public Shopify app for HyFib, with its credentials in configuration. The
     app uses the authorization code grant with an offline, expiring token (`expiring=1`), and the
     worker refreshes the token under a row lock, storing each pair atomically.
   - **Scopes:** `read_orders,read_products`. HyFib does not ask for customers or all orders.
   - **One company per store:** a store can be connected to one company at a time, because Shopify
     keeps one token per app and store (SH-007).
2. **Callback verification:**
   - **Shopify:** the callback is verified by HMAC, timestamp (±90 s), the `shop` pattern, and a
     single-use `state` bound to the member who started it. The member's session must still hold
     `commerce.manage` in that company.
   - **WooCommerce:** the key handover (WC-003) is unauthenticated. It is tied to a single-use
     random connect id, and the keys are trusted only after they authenticate against the store
     address the member entered.
3. **Webhooks:**
   - **Signals only:** a verified webhook only asks the worker to fetch the resource from the
     store's API. Nothing in its body is stored (Shopify payloads are cut to `id`, `updated_at`
     and `admin_graphql_api_id` with `includeFields`). Duplicates are recorded by delivery id
     (Shopify: `X-Shopify-Webhook-Id`; WooCommerce: `X-WC-Webhook-Delivery-ID`), and
     out-of-order deliveries cannot move a copy backwards, because the fetch always reads the
     current state.
   - **Destructive topics:** uninstall and redaction use the shop named in the signed body, never
     only the header, because the HMAC covers only the body (SH-024).
4. **Recovery:** webhooks can be lost:
   - Shopify deletes a subscription after 8 failures (SH-025).
   - WooCommerce disables a webhook after more than 5 failures and never retries (WC-018).

   So a scheduled incremental read by `updated_at` / `modified_after` catches up, and a periodic
   check re-creates missing subscriptions and re-enables disabled WooCommerce webhooks.
5. **Money:**
   - **Conversion:** Shopify `Decimal` strings and WooCommerce decimal strings are converted to
     integer minor units exactly, using the currency's exponent.
   - **More decimals than the currency allows:** a value with non-zero digits beyond it is
     unknown, not rounded.
   - **What is not used:** the WooCommerce line item `price` (a float) and the Shopify presentment
     amounts.
6. **WooCommerce access:**
   - **HTTPS only:** stores must be served over https (WC-005). HyFib never uses the query-string
     credentials fallback, because keys never go into URLs.
   - **Egress client:** all requests go through the egress client, with its address checks, no
     redirects and size and time limits.
   - **Webhook endpoint:** it answers the creation ping (WC-012) with 200 without treating it as an
     event.
7. **Uninstall and privacy:**
   - **Shopify `app/uninstalled`:** stops syncing and drops the tokens.
   - **`shop/redact`, or removal by the company:** deletes the store's data.
   - **`customers/redact`:** redacts the named orders for good (sticky).
   - **Removal from HyFib:** calls `appUninstall` for Shopify. For WooCommerce, HyFib deletes its
     webhooks and tells the owner to revoke the key, since the API cannot revoke keys.
8. **Messages on store events (P4-06c):**
   - **No new scopes:** shipments, tracking and payment gateways are read with `read_orders`
     (SH-030, SH-031). The fulfillment topics would need `read_fulfillments` (SH-033), so HyFib
     reads orders in transit again every few hours to see deliveries (SH-034).
   - **Shipped:** a Shopify order is shipped at its first shipment that is not cancelled or failed;
     a WooCommerce order at `completed`, dated by `date_completed_gmt` (WC-022). **Delivered:**
     Shopify only, when every shipment of a fully shipped order is delivered. WooCommerce has no
     delivered status.
   - **Cash on delivery:** WooCommerce's `payment_method` is `cod` (WC-021). For Shopify, HyFib
     recognises the gateway name Shopify gives as its example, "Cash on Delivery (COD)", or a name
     containing "cash on delivery"; other manual payment names are not treated as cash on delivery.
   - **Abandoned carts are not built:** a checkout has no phone of its own, so a number needs the
     customer (`read_customers`) or the addresses (protected customer data), WooCommerce has no
     carts to read (WC-023), and a reminder is a marketing message that needs marketing opt-in
     (research M-176).
