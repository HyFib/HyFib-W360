# Threat model

Last updated 2026-09-26. Status: **M** = mitigated and tested locally, **P** = partially mitigated,
**D** = designed (not yet built), **A** = accepted risk (documented).

## Assets

Customer conversations and contact data (per company); WhatsApp business tokens; payment references
and wallet balances; identity credentials and sessions; audit trails; platform administration power.

## Actors

Anonymous internet user · authenticated user of company A attacking company B · malicious or
compromised company member · compromised company owner account · malicious WhatsApp end user
(sends crafted messages/media) · forged provider (fake webhooks) · platform staff (insider) ·
supply-chain attacker · attacker with stolen database backup or read access.

## Trust boundaries

Browser ↔ web · Meta/Razorpay ↔ webhook endpoints · web/worker ↔ PostgreSQL (roles, RLS) ·
worker ↔ external APIs (egress) · platform area ↔ tenant area · secret manager ↔ processes.

## Threats and mitigations

| #   | Threat                                                                                                                | Mitigations                                                                                                                                                                                                                                                                                                                                        | Status                                  |
| --- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| T1  | **Cross-tenant data access** via guessed ids, missing filters, joins, exports, caches, jobs, SSE, AI retrieval        | FORCE RLS on every tenant table; transaction-local context failing closed; runtime roles without BYPASSRLS/ownership; composite keys; per-request membership verification; same 404 for non-members; signed job envelopes + RLS-scoped loading; no shared caching of app pages (`no-store`). SSE/AI/export paths reuse the same scopes (designed). | M (DB, web, jobs); D (SSE, exports, AI) |
| T2  | **Account takeover** (credential stuffing, phishing, session theft)                                                   | Scrypt password hashing (Better Auth), 12+ char passwords, DB-backed rate limits on sign-in/2FA/reset, TOTP 2FA mandatory for privileged roles after grace, HttpOnly SameSite=Lax Secure cookies, session list/revoke, revoke-all on password reset, 2FA account lockout (library). Breached-password check and WebAuthn are backlog.              | P                                       |
| T3  | **Enumeration** of accounts or companies                                                                              | Sign-up enumeration protection (synthetic response), generic reset responses, uniform 404 for company access. Company slug uniqueness reveals existence on creation (accepted: A).                                                                                                                                                                 | M / A                                   |
| T4  | **CSRF / cross-origin actions**                                                                                       | SameSite cookies; Next.js server-action Origin/Host check plus our exact trusted-origin check; Better Auth origin checks; POST-only mutations.                                                                                                                                                                                                     | M                                       |
| T5  | **XSS / message injection** (malicious message text, names, templates rendered in the inbox)                          | React escaping; strict CSP with nonces and `strict-dynamic`; no `dangerouslySetInnerHTML`; email templates HTML-escape all values. Message rendering sanitisation tests in phase 2.                                                                                                                                                                | P                                       |
| T6  | **Confused-deputy OAuth binding** (Embedded Signup assets bound to the wrong company; attacker substitutes a WABA id) | Server-side code exchange within the authenticated company context; `state` bound to session+company; verify returned WABA/phone ownership via the token's granted assets before binding; unique bindings per external asset; audit.                                                                                                               | D                                       |
| T7  | **Webhook forgery or replay**                                                                                         | HMAC-SHA256 over the raw body with constant-time compare (Meta, Razorpay); durable receipt with body hash + provider event id dedupe; idempotent consumers; unknown assets quarantined; security events for invalid signatures.                                                                                                                    | D                                       |
| T8  | **Bulk-send abuse / spam from a tenant**                                                                              | Consent and suppression checks at send time; template approval enforcement; per-number and per-tenant rate limits; plan quotas; platform suspension (blocks outbound, tested in jobs); abuse signals dashboard.                                                                                                                                    | P (suspension built)                    |
| T9  | **Billing fraud** (fake payment success, double credit, chargeback abuse, runaway auto-recharge)                      | Credit only after server-verified capture; unique provider references; append-only balanced ledger; single active recharge attempt; caps with headroom reservation; step-up auth for payment settings; chargebacks reverse funding and trigger review.                                                                                             | D                                       |
| T10 | **SSRF** through webhooks, HTTP automation nodes, imports, agent endpoints                                            | Central egress client: DNS resolution pinned per request, block private/loopback/link-local/metadata ranges and IPv6 equivalents, re-check after redirects (or disable redirects), size/time limits, allowlists per tenant.                                                                                                                        | D                                       |
| T11 | **Malicious media** (polyglots, oversized files, malware)                                                             | Type sniffing vs declared type, size limits per type, scanning before exposure, private bucket with short-lived tenant-scoped signed URLs, `Content-Disposition: attachment` for risky types.                                                                                                                                                      | D                                       |
| T12 | **Prompt injection / AI misuse**                                                                                      | Messages and documents treated as untrusted; tool calls independently authorised, schema-validated and allowlisted; high-impact actions need human approval; tenant-scoped retrieval; budgets; red-team tests.                                                                                                                                     | D                                       |
| T13 | **Secrets exposure** (tokens in logs, URLs, browser, exports)                                                         | Secrets only from the secret manager; AES-256-GCM encryption at rest with AAD; logger redaction; tokens never sent to browsers; email payloads erased after delivery; secret scanning in CI (gitleaks).                                                                                                                                            | P                                       |
| T14 | **Insider / platform abuse**                                                                                          | Platform role without BYPASSRLS; customer content only via reasoned, scoped, ≤8 h support grants visible to the company; platform actions mirrored into company audit logs; MFA required for platform staff; no impersonation.                                                                                                                     | M                                       |
| T15 | **Audit tampering**                                                                                                   | Append-only tables (privileges + trigger, even for the owner role); retention purge path separate. Hash-chained checkpoints exported to WORM storage are backlog.                                                                                                                                                                                  | P                                       |
| T16 | **Supply chain**                                                                                                      | Pinned versions + lockfile; pnpm minimum release age and explicit build-script allowlist; Dependabot; `pnpm audit` in CI; actions pinned by commit SHA; container scanning (Trivy).                                                                                                                                                                | P                                       |
| T17 | **Denial of service**                                                                                                 | Rate limits (auth), body size limits (server actions 1 MB; webhooks 4 MB designed), statement and idle-transaction timeouts, bounded queries and pagination; WAF/CDN at the edge (deployment).                                                                                                                                                     | P                                       |
| T18 | **Stolen backup / DB read access**                                                                                    | Encrypted storage and backups (provider); app-level encryption for tokens and queued secrets; session tokens readable only by `w360_auth` (accepted residual risk A: plaintext session tokens at rest in the auth schema).                                                                                                                         | P / A                                   |
| T19 | **Compromised application process**                                                                                   | Least-privilege roles limit blast radius (no DDL, no BYPASSRLS, column grants), but an attacker with app credentials can set any tenant context. Mitigate with secret rotation, runtime hardening, monitoring and incident runbooks.                                                                                                               | A                                       |
| T20 | **Membership revocation not applied to open sessions/queued work**                                                    | Membership re-checked on every request; actor-bound jobs re-check membership (tested); SSE re-validation (designed).                                                                                                                                                                                                                               | M / D                                   |

## Review cadence

Update this document with every phase gate. An external independent security review is required
before handling real customer data (see `docs/RELEASE-CHECKLIST.md`).
